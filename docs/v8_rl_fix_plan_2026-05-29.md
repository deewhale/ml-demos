# V8 RL 修复实施计划（2026-05-29）

> 配套 [docs/v8_rl_diagnosis_2026-05-29.md](v8_rl_diagnosis_2026-05-29.md)。
> **诊断结论**：战斗引擎健康（小怪 8-12 真实回合，"24-50 回合"是计数标错名的幻觉）；真问题是**奖励**——`-丢血 -0.5×回合` 的 shaping 引发 reward hacking → 模型 skip 所有卡 → 卡组永远 11 张烂牌 → 通关恒 0。且这套奖励**偏离了用户原设计**（用户设计的是"战后给卡组多维评分"，被 agent 在 commit `8b9485a` 换成了 hp/回合）。
> **本计划**：把用户的"每层懂行信号"设计落地，替换被改坏的奖励。
> **权责**：游戏理解 / 设计意图来自用户；RL / 工程实现细节由 Claude 定。下列技术细节（聚合公式、奖励形状、权重）是**初始设计**，实施中用"能解决问题 + 不引入新作弊"两轴边做边校验，可调。

## 目标阶梯
- 远期北极星：A20 90%（已知：人类顶尖铁甲都到不了，AI 无先例——作远期愿景，不作近期 KPI）。
- 当前目标：**通关 A0**（打过第三幕 boss）。
- 近靶：**稳定打过第一幕 boss**（现状 ~32%、通关 0）。

## 核心设计：恢复用户的"卡组评分"奖励

### 一句话
删掉 hp/回合战斗 shaping，换成"**牌组实力增长 + 真实进度**"作奖励；牌组实力由**战后从真实战斗里量的每张卡 5 维分**聚合而来；选卡 / 路线决策靠模型已有的回溯机制，从"后来牌组变强、走得更远"那里领奖励。

### 卡牌 5 维评分（每局重新长，上下文相关）
- **按局算，不跨局攒**：一张卡的价值高度依赖当前 relic / 血量 / 牌组组合，每局从零长 → 模型学到的是"这张卡跟我这套配着好"（build 层联动），不是绝对好坏。
- **锚（直接从战斗细账量，最实）**：
  - **输出** = 这张卡这局实打出的真实伤害（扣完格挡）累计。
  - **防御** = 这张卡这局加的格挡累计。（"格挡实际挡掉多少"追不到来源卡，只量"加了多少"。）
- **自举三维（用"当前高分卡"折算，build 自己长出核心卡）**：
  - **运转(draw)** = 这张卡抽到的牌的（当前）分之和——抽到高分卡才算成功。
  - **加费(energy)** = 这张卡给的能量 × 它促成多打出的（高分）卡的价值。
  - **能力(power)** = 上的 buff 层数 × 受影响攻击的估算额外收益。（下游伤害引擎不拆，用事后估算，权重保守。）
- **"核心卡"不预定义**：分一路涨、把牌组总分往上拉的卡，自然成为核心卡。
- **每张卡综合分** = 5 维归一化后的加权和；**锚维（输出/防御）权重高，估算维（能力下游、draw）权重保守**（初始值实施时定，两轴校验后调）。

### 牌组实力 + 奖励形状
- **牌组实力 = 全部卡综合分之和（总分，不是平均分）**。
  - 关键：用总分 → 拿到任何净正分的卡都让实力上升，**不存在"为保平均分而 skip"的动机**（这是第一层防 skip-all 保险）。
- **奖励（meta 策略，删掉 hp/回合后）**：
  1. **真实进度（稀疏、不可伪造、对齐北极星）**：到新楼层 +、过每个 act boss ++、通关 +++。这是 ground truth，无法作弊。
  2. **牌组实力增长（稠密、引导选卡）**：战后牌组总分的增量，经回溯（GAE）归给选卡 / 路线决策 → 选到日后证明强的卡就被正反馈。
  3. **删除** hp_lost / turns 的战斗惩罚（reward hacking 的源头）。
  4. **血量(战损)作路线资源，不作惩罚**：HP 是路线决策的状态输入（资源管理：强度够不够、要不要回血），其奖励影响只通过"死亡 / 进度"体现（早死 = 进度奖励低），**不设独立的每点血惩罚**。
- **为什么这次能跳出 skip-all**：以前 skip-all 被奖励（短仗=正分）；现在 skip-all → 卡组弱 → 早死 → 进度奖励低 = 负反馈。坑没了。总分设计是第一层保险，死亡/进度是第二层兜底。

## 六阶段实施

### 阶段 0 — 清场（低风险，先做）
- 拔掉战斗叶子评估里的 70% 随机噪声（`v8/combat_net_wrapper.py` 随机桩 → `neural_eval=None`，纯手写启发；隔离测试证明只会更稳）。
- 修两个标错名的计数：
  - 战斗 `turns`：实为动作数。改成真实回合数（战斗结束前缓存 `current_combat.state.turn`），或诚实改名 `turn_actions`。
  - `beat_boss`：实为 game_won。拆成 `a1_boss_killed` / `a2_boss_killed` / `won_game`，旧名留废弃别名。
- NEOW 选项 token 注入文字语义（`v8/action_space.py:280`，与 CARD_REWARD 一致）。
- 更正诊断文档中被推翻的结论（战斗根因那几条标注为"已推翻：计数 bug + 随机桩仅边缘影响"）。

### 阶段 1 — 导出战斗细账（5 维原料）
- 战斗引擎已逐卡逐效果记在 `CombatEngine.log.entries`（`combat_engine.py` play_card → effects），但战斗结束 `current_combat` 被置 None（`game.py:3913`）即丢弃，v8 从不读。
- 在 `_end_combat` 置 None 之前把 `log.entries` 导出，挂到 `CombatResult` 或回写 run_state，让 `v8/env.py` 在战斗退出时读到。
- 抽牌具体牌 id：`_draw_cards` 已返回，3 个调用方把返回值塞进 effects（~3 行）。
- 验收：能从一场真实战斗拿到 per-card {伤害, 格挡, 抽到的牌, 给的能量, 上的 buff}。

### 阶段 2 — 5 维评分 + 新奖励（设计大头）
- 实现按局滚动的 per-card 5 维评分（锚维直接量、自举三维引用当前分）。
- 实现牌组总分 = Σ 卡综合分。
- 改 `v8/reward.py`：删 hp/回合战斗惩罚；加"牌组总分增量 + 进度"奖励；HP 退为路线状态输入。
- **每加一个维度 / 每改一处奖励，跑两轴校验**：① 能解决问题（该信号确实把模型推向"会选卡"）② 不引入新作弊（不存在满足该信号却不进步的退化路径）。重点盯：估算维（能力下游、draw）会不会被钻。
- 注意：阶段 0 改了 action token，旧 ckpt 失效 → 配合阶段 3 从头训。

### 阶段 3 — 探索防崩 + 从头训
- 加**探索度地板 / 自适应熵系数**（`v8/trainer.py` 当前固定 ent_coef=0.01，无 floor）：熵跌破阈值（如初始熵 30%）自动上调；可加 KL 约束。
- **从头训**（fresh start，meta 策略随机初始化）——不从 v39 锁死 ckpt 续训（救不回来，文献 + 数据都指向）。战斗是搜索驱动，不受影响。
- 续训规范加触发条件：上批 final 熵 < 阈值（如 0.1）→ 强制 fresh start / 回滚。

### 阶段 4 — 评估 + 课程
- 评估指标分层：**`won_game` 为唯一北极星**，a1/a2 boss 当过滤器，**entropy 纳入每次 eval 输出**（崩了第一时间看见）。确定性 + 采样双轨。
- 难度课程（借鉴 Miles Oram 项目）：先把"打过第一幕 boss"当第一阶段 episode 终点 + 大奖励；稳定后延伸 act2 → 通关。对齐近靶。

### 阶段 5 — 跑 + 迭代 + 抽查
- 从头训，按 CLAUDE.md 训练迭代工作流：每批完成自动按决策树续 / 修 / 归因。
- 定时抽查：每 2-3 批拉 trace 对照 wiki；每 5 批 / 里程碑实机对照；隔离战斗测试常态化（`tools/v8_combat_isolated_test.py`，每改一次战斗量一次）。
- （用户设计里"让模型自己学战斗、自迭代提速"那块放到本阶段往后——现在搜索单干够用，等通关稳了再上。）

## 防钻空子红线（贯穿全程）
- 标准 RL 的核心教训：任何"人给的引导信号"设计不好都会被模型钻（这次 hp/回合就是；CoastRunners 绕圈刷分是经典）。
- 唯一有理论保证不改变最优策略的 shaping 是势差形式(PBRS)；我们的进度/牌组分不是严格 PBRS，所以**必须靠两轴校验 + 进度兜底**把关。
- 每个新信号上线前问两句：模型能不能"满足这个信号但不通关"？如果能，就是潜在作弊路径，要么改形状要么砍掉。

## Checkpoints / 报告纪律
- 每阶段完成给简短报告：改了什么、两轴校验结果、对下一阶段的影响。
- 阶段 0/1 是工程清理 + 埋点，做完各报一次。
- 阶段 2 是设计大头，5 维每维、奖励每项单独两轴校验后才并入。
- 阶段 3 起进入训练，按 CLAUDE.md 训练迭代决策树自动跑，里程碑（首次 a1 boss 稳定、首次通关）实机对照。
