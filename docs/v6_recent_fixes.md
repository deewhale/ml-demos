# V6 近期修复记录

## 修复 1：出牌奖励算错了位置

**问题：** 之前每打一张牌立刻算奖励。但敌人是回合结束后才打你的，所以"这回合掉了多少血"被算到了下一回合的第一张牌上。结果 agent 学到"出牌=好，结束回合=坏"，而不是学会根据情况选择攻防。

**改动：** `combat_act()` 方法（约 1545-1599 行）。每张牌先存到 `turn_buffer`，不给分。等回合结束后统一算分，平均分配给这回合所有出牌。

算分公式：`造成伤害 × 0.05 + 击杀数 × 1.0 - 掉血 × 0.1`

## 修复 2：选牌奖励是写死的假数据

**问题：** 之前选牌按稀有度给固定分（普通卡 0.1，稀有卡 0.5）。这个分数跟卡好不好用完全无关，是硬编码的假数据。

**改动：** `on_combat_end()` 方法（约 2053-2100 行）。选牌时给 0 分，打完战斗后根据实际掉血量回头给之前的选牌补分。离得近的战斗影响大（×1.0），离得远的影响小（×0.7^n），Boss 战权重 ×3，精英战 ×2。

## 修复 3：防卡死机制在战斗中误触发

**问题：** 有个防卡死逻辑：连续 4 次游戏状态一样就判定卡死，强制结束回合。判定用的签名是 `画面|操作列表|能量|手牌数`。但每回合开始能量和手牌数都会重置为一样的值（比如 3 能量、5 手牌），所以正常打牌到第 5 回合就会误触发。触发后 agent 被迫不出牌直接结束回合，白吃一轮伤害。整个训练过程约 20000 次误触发。

**改动：** `decide()` 方法（约 2189-2214 行）。加了判断 `in_combat_now = bool(gs.get("combat_state"))`，战斗中跳过整个防卡死检测。非战斗画面（地图、事件、商店）照常检测。

## 修复 4：估值函数更新幅度没有限制

**问题：** PPO 训练有两个部分——策略（选什么动作）和估值（预测当前局面能拿多少分）。估值的作用是当参照物：实际拿分比预测高 → 这个动作好，比预测低 → 这个动作差。之前估值更新没有限制幅度，一次异常数据就能让预测值从 5 跳到 50，后续所有"好/差"的判断都基于这个错误的参照物，训练方向变成随机。这就是为什么 value loss 从 0.37 跳到 43。

**改动：** `ppo_update()` 方法（约 1085-1088 行）。给估值更新加了幅度限制（±0.2），每次最多只能变化这么多，跟策略更新的限制保持一致。

## 修复 5：战斗和策略决策混在一起评分

**问题：** 训练更新时需要把所有决策的"好坏程度"缩放到同一个范围（归一化）。之前战斗决策（每局约 50 条）和策略决策（选牌/选路，每局约 5 条）混在一起算。战斗占 90%，策略决策的评分被战斗的数据带偏，更新幅度不可控。

**改动：** `ppo_update()` 方法（约 1044-1054 行）。战斗和策略分开归一化，各算各的均值和标准差。
